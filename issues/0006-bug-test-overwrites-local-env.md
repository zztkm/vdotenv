## 目的

テストの実行で、開発者が作業ディレクトリに置いた設定ファイルを破壊しない。

## 現状

対象は `Makefile` の `test` ターゲット。
`clean` ターゲット、`vdotenv_test.v` の既定ファイルを参照するテスト、`.github/workflows/ci.yml` の Tests ステップも関連する。

`make test` は `testdata/.env` と `testdata/.env.parse` を作業ディレクトリへコピーする。
同名ファイルが存在しても退避せずに上書きし、テスト成功後には両方を削除する。
テスト失敗時は削除処理まで進まないが、元の内容はすでに失われている。
`make clean` も同名ファイルを無条件に削除する。

macOS、公式 V 0.5.2（7647ce1）、コミット `a01d748` の一時コピーで、実行前に用意したダミーの設定ファイルが `make test` 成功後に削除されることを確認した。

## 再現手順

実際の設定ファイルがあるディレクトリでは実行しない。
公式 V 0.5.2 が PATH にある環境で、リポジトリから次を実行する。

```sh
scratch=$(mktemp -d)
git archive HEAD | tar -x -C "$scratch"
(
    cd "$scratch"
    printf 'LOCAL_CONFIG=should_survive\n' > .env
    printf 'LOCAL_PARSE_CONFIG=should_survive\n' > .env.parse
    make test
    test ! -e .env && test ! -e .env.parse
)
```

最後の確認が成功する。
本来は、テスト実行後も両ファイルと元の内容が保持される必要がある。

## 影響と成立条件

優先度は高。ただし影響は開発・テスト環境に限られる。
作業ディレクトリに既存の `.env` または `.env.parse` がある状態で `make test` を実行すると、その設定を失う。
コミットされていない設定は Git から復元できるとは限らない。

ライブラリのファイル出力 API の権限問題とは別で、開発用コマンドによるデータ破壊である。

## 設計方針

- テスト専用の一時ディレクトリでフィクスチャを読み込み、作業ディレクトリの設定ファイルには触れない。
- テストの成功・失敗のどちらでも、一時ファイルを後始末する。
- バックアップによる方式を採用する場合は、失敗・中断時の復元と元のファイル属性の保持も検証する。
- `clean` が利用者の設定ファイルを削除しないよう、削除対象をテスト専用の成果物に限定する。
- CI とローカルのテスト手順を整合させる。
