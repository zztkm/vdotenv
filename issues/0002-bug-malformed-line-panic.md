# 区切り文字のない行を解析すると panic が発生する

- Created: 2026-10-03
- Completed: {YYYY-MM-DD}
- Branch: feature/fix-malformed-line-panic
- Polished: {YYYY-MM-DD}

## 目的

不正な dotenv 入力によるプロセスの停止を防ぎ、解析エラーを呼び出し元で処理できるようにする。

## 現状

対象は `vdotenv.v` の `parse_lines()`、`parse_contents()` と、それらを使用する公開 API。

`parse_lines()` は `=` の存在を確認せず、`new_line.split('=')[1]` にアクセスする。
区切り文字のない行では配列の範囲外アクセスになり、panic が発生する。
空白だけの行や先頭に空白のあるコメントも、現在の空行判定とコメント判定では除外されない。

macOS、V 0.5.2 c0e8c7b、コミット `70988e0` の一時コピーで `INVALID_LINE` による panic を再現した。
既存テストは通過するが、この入力はカバーしていない。

## 再現手順

リポジトリの一時コピーに次のテストを追加し、`v test malformed_probe_test.v` を実行する。

```v
module vdotenv

fn test_malformed_line() {
    unmarshal('INVALID_LINE')
}
```

実行結果は次のとおりで、テストプロセスが失敗する。

```text
V panic: array.get: index out of range (i,a.len):1, 1
```

## 影響と成立条件

攻撃者が `unmarshal()` の入力文字列、または読み込まれるファイルの内容を操作できる場合、アプリを停止させる DoS につながる。
入力を信頼できるローカルファイルに限定している場合でも、設定ファイルの記述ミスで起動に失敗する。

## 設計方針

- 空白を考慮して空行とコメント行を判定する。
- 最初の `=` の有無を検証してからキーと値を取り出す。
- 不正な行を panic ではなく解析エラーとして返し、必要に応じて行番号を付ける。
- エラーの内容に秘密情報を含む行全体や値を出力しない。
- `unmarshal()`、`load()`、`over_load()`、`parse()` などへのエラー伝播と API 互換性を整理する。

## 完了条件

- [ ] `INVALID_LINE` を解析しても panic が発生せず、呼び出し元が解析エラーを判別できる。
- [ ] 空白だけの行と先頭に空白のあるコメントを無視できる。
- [ ] 正常な行と不正な行を混在させた入力でも、範囲外アクセスが発生しない。
- [ ] 文字列の解析とファイル経由の読み込みに回帰テストがある。
- [ ] エラー表示に秘密情報の値が含まれず、既存テストが通る。
- [ ] エラー処理の仕様と公開 API の変更がドキュメントに反映されている。
