# 区切り文字のない行を解析すると panic が発生する

- Created: 2026-10-03
- Completed: {YYYY-MM-DD}
- Branch: feature/fix-malformed-line-panic
- Polished: {YYYY-MM-DD}

## 目的

不正な dotenv 入力によるプロセスの停止を防ぎ、解析エラーを呼び出し元で処理できるようにする。

## 現状

対象は `vdotenv.v` の `parse_lines()`、`parse_contents()` と、それらを使用する公開 API。

`parse_lines()` は `=` の存在を確認せず、`new_line.split('=')[1]` にアクセスする。
区切り文字のない行では配列の範囲外アクセスになり、panic が発生する。
空白だけの行や先頭に空白のあるコメントも、現在の空行判定とコメント判定では除外されない。

macOS、V 0.5.2 c0e8c7b、コミット `70988e0` の一時コピーで `INVALID_LINE` による panic を再現した。
既存テストは通過するが、この入力はカバーしていない。

## 再現手順

リポジトリの一時コピーに次のテストを追加し、`v test malformed_probe_test.v` を実行する。

```v
module vdotenv

fn test_malformed_line() {
    unmarshal('INVALID_LINE')
}
```

実行結果は次のとおりで、テストプロセスが失敗する。

```text
V panic: array.get: index out of range (i,a.len):1, 1
```

## 影響と成立条件

攻撃者が `unmarshal()` の入力文字列、または読み込まれるファイルの内容を操作できる場合、アプリを停止させる DoS につながる。
入力を信頼できるローカルファイルに限定している場合でも、設定ファイルの記述ミスで起動に失敗する。

## 設計方針

- 空白を考慮して空行とコメント行を判定する。
- 最初の `=` の有無を検証してからキーと値を取り出す。
- 不正な行を panic ではなく解析エラーとして返し、必要に応じて行番号を付ける。
- エラーの内容に秘密情報を含む行全体や値を出力しない。
- `unmarshal()`、`load()`、`over_load()`、`parse()` などへのエラー伝播と API 互換性を整理する。

## 完了条件

- [x] `INVALID_LINE` を解析しても panic が発生せず、呼び出し元が解析エラーを判別できる。
- [x] 空白だけの行と先頭に空白のあるコメントを無視できる。
- [x] 正常な行と不正な行を混在させた入力でも、範囲外アクセスが発生しない。
- [x] 文字列の解析とファイル経由の読み込みに回帰テストがある。
- [x] エラー表示に秘密情報の値が含まれず、既存テストが通る。
- [x] エラー処理の仕様と公開 API の変更がドキュメントに反映されている。

## 実装前の確認

現行の `parse_lines()` は最初の `=` の存在確認と空白の除去を実装済みで、元の panic は解消していた。
ただし、不正な行、空のキー、不正な引用値を黙って読み飛ばしており、呼び出し元への解析エラー通知は未実装だった。
既存の Result 型 API である `print_file()` と `print_terminal()` に回帰テストを追加し、エラーが返らないため 2 件のテストが失敗することを確認した。
テストのみをコミットしてから修正を開始した。

## 解決方法

- `parse_lines()`、`parse_contents()` を Result 型に変更し、不正な行には `ParseError` を返す。
  エラーには 1 始まりの物理行番号と固定の理由だけを含め、入力行、キー、値を含めない。
- `unmarshal()`、`parse()`、`load()`、`over_load()` と出力 API に解析エラーを伝播させる。
  ファイル全体の解析に成功してから環境変数を設定し、解析エラー時には出力を生成しない。
  複数ファイルの読み込みでは先に成功した設定を保持し、不正なファイルと後続のファイルは適用しない。
  公開 API の破壊的変更と移行方法を README、API ドキュメント、CHANGELOG、サンプルに反映した。
- 文字列、既定ファイル、明示したファイル、複数ファイルについて、区切り文字の欠落、空のキー、不正な引用値、空白とコメント、CRLF の行番号、秘密情報を含まないエラー、部分適用の防止を検証した。
  `make test`、`v fmt -verify .`、`v vet -W .`、`git diff --check` が通過した。
  外部モジュールから `ParseError` を判別できることと、解析エラー時に `print_terminal()` が環境変数の値を出力しないことも実行で確認した。
