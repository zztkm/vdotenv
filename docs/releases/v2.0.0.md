# v2.0.0 リリースノート

v2.0.0 は、入力検証、シリアライズ、JSON 出力、端末表示の安全性を改善するメジャーリリースです。
v1.0.0 から更新する場合は、エラー処理とファイル出力の呼び出しを変更してください。
全変更は [CHANGELOG](../../CHANGELOG.md) に記載しています。

## 公開 API の変更

次の API が Result 型を返すようになります。
`or { ... }` で処理するか、Result 型を返す関数内で `!` を使って伝播してください。

| API | v1.0.0 の戻り値 | v2.0.0 の戻り値 |
| --- | --- | --- |
| `load()` | 戻り値なし | `!` |
| `over_load()` | 戻り値なし | `!` |
| `marshal()` | `string` | `!string` |
| `unmarshal()` | `map[string]string` | `!map[string]string` |
| `parse()` | `string` | `!string` |
| `print_terminal()` | 戻り値なし | `!` |

```v
import os
import zztkm.vdotenv

fn main() {
    vdotenv.load() or {
        if err is vdotenv.ParseError {
            eprintln('Invalid dotenv input on line ${err.line}')
        } else {
            eprintln(err.msg())
        }
        return
    }

    env_map := { 'APP_MODE': os.getenv('APP_MODE') }
    encoded := vdotenv.marshal(env_map) or { panic(err) }
    decoded := vdotenv.unmarshal(encoded) or { panic(err) }
    assert decoded == env_map
    // Save encoded with your application's own file writer and permission policy.
}
```

`write()` と `print_file()` は削除します。
`write(env_map, filename)` の代わりに、`marshal(env_map)` の結果をアプリケーション側の書き込み処理で保存してください。
`print_file()` の代わりに、`.env` を `unmarshal()` で解析し、各キーの現在のプロセス環境の値を取得したマップを `marshal()` に渡してください。
保存先、権限や ACL、上書き方法、書き込みエラーの処理は呼び出し元で決定します。
秘密情報を保存する場合は、POSIX の `0600` や Windows の ACL など、アプリケーションの保護方針を適用してください。

## 入力形式とエラー処理

- 不正な行や引用値は、入力の実値を含まない `ParseError` として通知します。
  `line` は入力またはファイル内の物理行番号（1 始まり）で、`reason` は安全な理由です。
- `load()`、`over_load()`、`parse()` は、キーや値に NUL があれば拒否します。
  設定から NUL を除去してください。
  `unmarshal()` と `marshal()` のメモリ内の値の往復変換は維持しますが、NUL を含む文字列を OS の設定関数へ直接渡さないでください。
- `load()` と `over_load()` は、ファイル全体の検証に成功してから環境変数を適用します。
  検証エラー時にはそのファイルを部分適用しませんが、複数ファイルのうち先に成功した設定は保持します。
  OS の設定失敗もエラーとして通知しますが、その時点ですでに適用した変数を元に戻すことはしません。
- `load()` は空の値も含め、既存の環境変数を保持します。
  上書きする場合は `over_load()` を使用してください。
- ファイル名の先頭と末尾の空白を除去せず、指定したパスをそのまま読み込みます。
- 入力先頭の UTF-8 BOM を 1 個だけ無視します。
  値や途中のキーに含まれる同じ文字と、解析エラーの物理行番号は保持します。

存在しないファイルや読み込めないファイルは、従来どおり診断を表示して空の入力として扱います。
この場合は読み込み API のエラーにならないため、ファイルの存在が必須なら呼び出し元で確認してください。

## 保存形式と表示形式の変更

`marshal()` は `KEY="VALUE"` 形式で出力し、キーを `[A-Za-z_][A-Za-z0-9_]*` に制限します。
バックスラッシュ、二重引用符、LF、CR、タブをそれぞれ `\\`、`\"`、`\n`、`\r`、`\t` にエスケープし、値による別の環境変数の追加を防ぎます。
旧版の読み込み処理では復元できない場合があるため、保存と読み込みの両方を新しい形式に対応させてください。

単一引用符内の値はリテラルとして扱います。
`TEXT='line\nbreak'` の改行を復元したい場合は、`TEXT="line\nbreak"` に変更してください。
二重引用符内では既知のエスケープを復元し、未知のエスケープはバックスラッシュごと保持します。
物理的な複数行の引用値と変数展開には対応しません。

`print_terminal()` は保存用のシリアライズとは別の表示専用形式を使用します。
LF、CR、タブ以外の C0 制御文字と DEL は `\xNN`、Unicode の C1 制御文字は `\u00NN` で表示し、不正な UTF-8 は置換文字に変換します。
端末出力を保存したり復元したりする処理は、元の値のマップを `marshal()` でシリアライズする方法に変更してください。

## JSON 出力の変更

`parse(false, ...)` はキーと値を JSON エスケープしたフラットなオブジェクトを返し、プロセス環境を変更しません。
出力テキストを直接比較せず、JSON デコードして取得してください。

```v
import json
import zztkm.vdotenv

fn main() {
    output := vdotenv.parse(false) or { panic(err) }
    env_map := json.decode(map[string]string, output) or { panic(err) }
    println(env_map['APP_MODE'])
}
```

`parse(true, ...)` はファイル名のブロックコメントを含むため、厳密な JSON ではありません。
ファイル名のラベルは JSON エスケープ済みの文字列内容で、すべての `/` をさらに `\u002f` に変換します。
ラベルを取得する処理は、二重引用符で囲んで JSON デコードしてください。

空ファイルによって不正なカンマは追加しません。
異なるファイル間の重複キーはファイル順に残り、どの値を採用するかは JSON デコーダーに依存します。
移植可能な結果が必要なら、ファイル間でもキーを一意にしてください。

## 検証環境

公式 V 0.5.2 の Linux と macOS で、回帰テスト、統合テスト、整形、lint を検証しています。
Windows と V の開発版は検証対象に含めていません。
V の開発版では標準の `json` モジュールが削除されているため、公式 V 0.5.2 を使用してください。
